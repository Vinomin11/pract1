# Эмулятор командной строки UNIX-подобной ОС

## Общее описание

Данный проект представляет собой эмулятор командной строки
UNIX-подобной операционной системы, разработанный в рамках
практической работы по дисциплине «Конфигурационное управление»
(Вариант №17).

Эмулятор реализует цикл REPL (Read-Eval-Print Loop) и поддерживает
базовый набор команд, имитирующих работу в командной строке Linux.
На текущем этапе команды `ls` и `cd` являются заглушками, которые
выводят своё имя и аргументы.

Приложение написано на Python 3 и использует только стандартную
библиотеку (`argparse`, `sys`).

## Описание функций и настроек

### Поддерживаемые команды

| Команда  | Описание                                        | Пример использования |
|----------|-------------------------------------------------|----------------------|
| `ls`     | Выводит имя команды и переданные аргументы       | `ls -la /home`       |
| `cd`     | Выводит имя команды и переданные аргументы       | `cd docs`            |
| `exit`   | Завершает работу эмулятора                       | `exit`               |

**Примечание:** команды `ls` и `cd` на этапах 1–2 являются
заглушками и выводят строку вида `Заглушка ls. Аргументы: ['-la']`.
Реальная логика работы с файловой системой появится на этапе 3–4.

### Параметры командной строки

| Параметр                | Описание                                        | Пример                              |
|-------------------------|-------------------------------------------------|-------------------------------------|
| `--vfs-path <путь>`     | Путь к файлу виртуальной файловой системы       | `--vfs-path vfs/vfs_deep.xml`       |
| `--script-path <путь>`  | Путь к стартовому скрипту с командами           | `--script-path scripts/default.txt` |

При запуске эмулятор выводит отладочную информацию обо всех
заданных параметрах в формате `ключ = значение`.

### Особенности работы

- **Приглашение к вводу** содержит имя VFS и имеет вид `VFS:~$ `.
  Имя VFS задаётся при создании эмулятора и отображается в
  приглашении к каждому вводу.
- **Парсер команд** разделяет ввод по пробелам на команду и
  аргументы. Пустая строка игнорируется.
- **Обработка ошибок:**
  - неизвестная команда → выводится сообщение
    `Ошибка: неизвестная команда '<имя>'`;
  - Ctrl+C или Ctrl+D → корректное завершение программы.
- **Стартовый скрипт** выполняется построчно. Строки, начинающиеся
  с `#`, и пустые строки игнорируются. **Ошибочные строки
  пропускаются, выполнение продолжается** — это требование
  варианта №17.
- **Имитация диалога:** при выполнении стартового скрипта перед
  каждой командой печатается приглашение и сама команда, чтобы
  создавалось впечатление ручного ввода.

## Команды для сборки проекта и запуска тестов

### Требования

- Python 3.10 или выше
- Git
- Bash (для запуска вспомогательных скриптов)

### Запуск в интерактивном режиме

```bash
# Запуск без параметров
bash run.sh

# Запуск напрямую
python3 src/shell_emulator.py
```

### Запуск с параметрами

```bash
# С указанием VFS
python3 src/shell_emulator.py --vfs-path vfs/vfs_deep.xml

# С указанием стартового скрипта
python3 src/shell_emulator.py --script-path scripts/script_default.txt

# С обоими параметрами
python3 src/shell_emulator.py \
    --vfs-path vfs/vfs_deep.xml \
    --script-path scripts/script_default.txt
```

### Запуск тестов

```bash
bash run_tests.sh
# или
python3 -m unittest discover -s tests
```

### Тестовые скрипты

Скрипты из папки `scripts/` запускают эмулятор с разными
параметрами и используются для проверки обработки аргументов
командной строки.

| Скрипт                         | Назначение                                                     |
|--------------------------------|----------------------------------------------------------------|
| `scripts/test_default.sh`      | Запуск без параметров.                                         |
| `scripts/test_vfs_path.sh`     | Запуск с указанием VFS и стартового скрипта.                   |
| `scripts/test_invalid_vfs.sh`  | Запуск с несуществующим файлом VFS: проверка обработки ошибки. |

**Запуск скриптов** (в Git Bash или Linux-терминале):

```bash
bash scripts/test_default.sh
bash scripts/test_vfs_path.sh
bash scripts/test_invalid_vfs.sh
```

## Примеры использования

### Интерактивный режим

```console
VFS:~$ ls
Заглушка ls. Аргументы: []
VFS:~$ ls -la /home
Заглушка ls. Аргументы: ['-la', '/home']
VFS:~$ cd docs
Заглушка cd. Аргументы: ['docs']
VFS:~$ foobar
Ошибка: неизвестная команда 'foobar'
VFS:~$ exit
Выход из эмулятора.
```

### Работа со стартовым скриптом

Содержимое `scripts/script_default.txt`:

```text
# Тестовый стартовый скрипт
# Строки, начинающиеся с #, игнорируются
ls
ls -la /home
cd
cd docs
foobar
exit
```

Запуск:

```bash
python3 src/shell_emulator.py --script-path scripts/script_default.txt
```

Результат (фрагмент):

```console
=== Параметры эмулятора ===
vfs_name    = 'VFS'
vfs_path    = None
script_path = 'scripts/script_default.txt'
===========================
Выполняется стартовый скрипт: scripts/script_default.txt
VFS:~$ ls
Заглушка ls. Аргументы: []
VFS:~$ ls -la /home
Заглушка ls. Аргументы: ['-la', '/home']
VFS:~$ cd
Заглушка cd. Аргументы: []
VFS:~$ cd docs
Заглушка cd. Аргументы: ['docs']
VFS:~$ foobar
Ошибка: неизвестная команда 'foobar'
VFS:~$ exit
Выход из эмулятора.
```

**Обратите внимание:** после `foobar` эмулятор **не остановился**,
а продолжил выполнение следующей команды `exit`. Это требование
варианта №17.

### Обработка ошибок

```console
VFS:~$ foobar
Ошибка: неизвестная команда 'foobar'

VFS:~$ exit
Выход из эмулятора.
```

При запуске с несуществующим стартовым скриптом:

```console
=== Параметры эмулятора ===
vfs_name    = 'VFS'
vfs_path    = None
script_path = 'scripts/nope.txt'
===========================
Выполняется стартовый скрипт: scripts/nope.txt
Ошибка: стартовый скрипт 'scripts/nope.txt' не найден.
Добро пожаловать в эмулятор оболочки (VFS).
Введите 'exit' для выхода.
VFS:~$ 
```

Эмулятор сообщает об ошибке и переходит в интерактивный режим —
программа не падает.
